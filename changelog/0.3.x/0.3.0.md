# 0.3.0 — 2026-09-24

## Added

- **`openaq_get_measurements` `effectiveRange`** echoes the UTC bounds sent to OpenAQ (`null` for an omitted bound). ([#29](https://github.com/cyanheads/openaq-mcp-server/issues/29))
- **`openaq_get_measurements` `gapCount` and `gaps`** on hourly and daily responses: missing intervals (a span between buckets that do not touch, or a null-value bucket) counted over every pulled row, with the first 20 listed. Raw responses carry neither. ([#29](https://github.com/cyanheads/openaq-mcp-server/issues/29))
- **`openaq_get_measurements` clipped-edge notice** when the range cuts the first or last hourly/daily bucket, so that bucket aggregates only the in-range part. ([#29](https://github.com/cyanheads/openaq-mcp-server/issues/29))
- **`provider` and `providerId` on `location`** in `openaq_get_readings` and `openaq_get_measurements`, plus `timezone` on `openaq_get_measurements`, taken from the location lookup each handler already makes and rendered in the text output. ([#30](https://github.com/cyanheads/openaq-mcp-server/issues/30))

## Changed

- **Behavior change: a date-only `datetimeFrom`/`datetimeTo` on `openaq_get_measurements` is the station's local calendar day** — it opens at local midnight and closes at the next one (23 or 25 hours on a DST day), where it was a UTC day ending `T23:59:59Z`. The same input sends different bounds; `effectiveRange` shows them. A station with no timezone, or one the runtime does not recognize, falls back to UTC days with a notice. ([#29](https://github.com/cyanheads/openaq-mcp-server/issues/29))
- **Behavior change: missing upstream values stay `null`.** `coordinates` on `openaq_find_locations` and `openaq_get_readings` is `null` unless both latitude and longitude are numbers, and `country` and `provider` on `openaq_find_locations` are `null` when OpenAQ lists none — no more `0,0`, `XX`, or `Unknown`. The text renders each as "not listed by OpenAQ". ([#40](https://github.com/cyanheads/openaq-mcp-server/issues/40))
- **Behavior change: `openaq_get_readings` coordinate resolution compares up to 1,000 candidate stations** (was 100), since `/v3/locations` pages by id and a 100-row pool missed newer, nearer stations. A full 1,000-row page adds a `notice` that the station is the nearest of the first 1,000. ([#22](https://github.com/cyanheads/openaq-mcp-server/issues/22))
- **Docs:** README and `docs/design.md` cover the new measurement, readings, and location outputs, with decision-log entries; the README tool table and capability reference are condensed.

## Fixed

- **`openaq_get_measurements` pull stops at exactly 5,000 rows.** A `limit` that does not divide 5,000 no longer overshoots; rows sliced off the last page still count toward `totalCount`, and a rollup series ending on the ceiling reads as complete when OpenAQ's exact total matches. ([#38](https://github.com/cyanheads/openaq-mcp-server/issues/38))
- **`openaq_get_measurements` rejects a `datetimeFrom`/`datetimeTo` that is not a real calendar date or time** (`2026-02-30`, `2026-13-01`, `T24:00:00Z`) at the schema, before any request, instead of forwarding it to OpenAQ. The advertised pattern is unchanged.
- **`openaq_get_measurements` notices suggest only a coarser aggregation than the one requested**, and none for a daily series.
- **Descriptions:** `openaq_get_measurements` `datetimeFrom` says an omitted start begins at the sensor's earliest data, and `percentComplete` can exceed 100 on a DST fall-back hour; `openaq_list_countries` `query` says a two-letter value falls back to substrings when no code matches.
