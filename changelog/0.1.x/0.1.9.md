# 0.1.9 — 2026-09-20

## Added

- **`.github/workflows/codeql.yml`** — CodeQL analysis on push, pull request, and a weekly schedule. The only workflow this repo carries; typecheck, lint, and tests stay local.
- **`bun run audit:fix`** — wraps `bun audit fix`, the first response to a transitive advisory, ahead of `bun update <name>` and `bun dedupe`.

## Changed

- **With `MCP_SESSION_MODE` unset the server now resolves to `stateless` from the `sessionMode: 'stateless'` declaration in `src/index.ts`**; an explicit `MCP_SESSION_MODE` still overrides it. Previously an unset value resolved `auto` → stateful; the `Dockerfile` already pinned `stateless`, so only the source-run default and `.env.example` moved.
- **The `canvas_id` input on `openaq_dataframe_query`, `openaq_dataframe_describe`, and `openaq_get_measurements` now advertises `pattern: ^[A-Za-z0-9_-]{10}$`.** A malformed id is rejected at argument validation before any canvas lookup; a well-formed id that is unknown or expired still returns `canvas_not_found`.
- **Nullable output fields render as `type: ["string", "null"]`** where they previously rendered as an `anyOf` of two primitives — a rendering change from `zod ^4.4.3 → ^4.6.5`, with identical semantics.
- **An argument rejection classifies as `InvalidParams` (`-32602`)**, not `ValidationError`, and carries `data.reason: "invalid_arguments"` with a schema-derived recovery hint.
- **Tool error text closes with the declared reason and retryability** — `(reason no_search_scope · not retryable)`. A test pinning an error's `content[0].text` or its old error code has to move.
- **`engines.bun` `>=1.3.0` → `>=1.4.0`.**
- **The plugin manifests collect `OPENAQ_API_KEY` from the host** — Claude Code through a `userConfig` prompt, Codex through `env_vars`. Both previously received an unsubstituted placeholder, which reads as unset.
- **The four upstream reasons are marked `thrownBy: 'service'`** on every definition that routes through `upstreamFailure`, so `error-contract-unthrown` keeps checking only what a handler throws.
- **The skill tree moved from `skills/` to `framework-skills/`.** Claude Code and Codex auto-load a plugin's root `skills/`, so the old path handed these development skills to every installing agent. Not shipped in the npm tarball either way.
- **README restructured around a capability reference** — one overview table, then a block per tool and resource, with the DataCanvas spill workflow as its own section.
- **Scaffolded scripts, the changelog template, and the issue templates resynced to 0.13.6.** `devcheck.config.json` gains the `lint` block that carries the truncation allowlist.
