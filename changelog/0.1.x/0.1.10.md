# 0.1.10 — 2026-09-22

## Fixed

- **`openaq_get_measurements` reports `pulledCount`/`pullComplete` and floors `totalCount`** instead of publishing the rows it managed to pull as the series total; `totalCountIsLowerBound` flags a floor read from OpenAQ's `">N"` shape. (#23)
- **`format()` on `openaq_get_measurements` and `openaq_dataframe_query` renders every row the response carries** — text-only clients no longer see a slice (20 of 100, 50 of N) that structuredContent clients don't. (#24)
- **`openaq_dataframe_query` caps responses at 200 rows**, forwarding `truncated` and naming `ORDER BY <column> LIMIT 200 OFFSET <n>` as the continuation; the canvas's 10,000-row default was a DuckDB ceiling, not a response budget. (#25)
- **Staging and error notices point callers at `openaq_dataframe_describe` before `openaq_dataframe_query`** — the staged table is flat while the response `series` is nested, so SQL written from the response shape alone named columns that don't exist. (#32)
- **A supplied `canvas_id` on `openaq_get_measurements` stages the series whatever its size**, so a narrow range no longer silently drops the id with no `canvasId` and nothing to join against. (#35)
- **Re-staging the same sensor on a reused canvas discloses that it replaced the earlier table**, rather than overwriting it silently. (#36)
