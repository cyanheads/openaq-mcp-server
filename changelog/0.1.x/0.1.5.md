# 0.1.5 — 2026-07-26

## Fixed

- **Declared upstream error reasons now reach the client** — `openaq_find_locations`, `openaq_get_readings`, `openaq_get_measurements`, `openaq_list_parameters`, and `openaq_list_countries` route their `OpenAqService` calls through a new `withUpstream`/`upstreamFailure` helper (`src/mcp-server/tools/shared/upstream-errors.ts`) that maps a caught service error onto the tool's own declared contract: `upstream_error` (5xx), `rate_limited` (429, preserving `retryAfter`), `upstream_timeout`, and `invalid_api_key` (401). Previously the service's raw framework throws carried no `reason`, so every declared `upstream_error` entry was dead and callers got no `Recovery:` line on the failure class they were most likely to hit. ([#16](https://github.com/cyanheads/openaq-mcp-server/issues/16))
- **`OpenAqService.request()` timeout classification** — the deadline branch now throws the framework `timeout()` factory (`-32004`) instead of `serviceUnavailable` (`-32000`), so a slow upstream is distinguishable from a broken one at the wire's error code, not just its message.
- **`OpenAqService` 401 handling** — a new `unauthorized()` branch in `throwForStatus` stops a rejected or missing API key from falling into the 5xx catch-all and being retried three times (~2.7s) before failing; it now fails in one attempt (~0.05s) as non-retryable.
- **`openaq_get_readings` misreported failure modes** — three fixes, all live-probed against a running server: a `parametersId` the station has no sensor for now throws `parameter_not_at_location` with an `available` id list, matching `openaq_get_measurements`, instead of misreporting as a dormant station via `no_recent_values`; the exactly-one-of `locationId`/`coordinates` guard gets its own `invalid_location_scope` reason instead of reusing `missing_coordinates_parameter`'s mismatched recovery; the nearest-station sweep radius is now a named constant at the OpenAQ API maximum, and `no_station_near_coordinates`'s recovery no longer suggests widening past it. ([#13](https://github.com/cyanheads/openaq-mcp-server/issues/13))
- **Canvas error contracts declared** — `openaq_dataframe_describe` and `openaq_dataframe_query` now declare `canvas_not_found`, and `openaq_dataframe_query` also declares `missing_table`; the framework already threw both (from `canvas.acquire()` and `instance.query()` respectively) with no advertised contract entry. Contract/linter correctness only — `tools/list` never advertises `errors[]` to clients, and the wire payloads already carried the framework's own reason and recovery hint. ([#16](https://github.com/cyanheads/openaq-mcp-server/issues/16))
