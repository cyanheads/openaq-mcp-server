# 0.1.7 — 2026-07-26

## Fixed

- **`openaq_dataframe_query` escapes Markdown table cells** — `format()` routes every header and row value through a new `escapeCell` helper (`src/mcp-server/tools/definitions/dataframe-query.tool.ts`): backslash doubles, `|` escapes, and `\r\n`/`\r`/`\n` collapse to `<br>`. Column names get the same treatment since they're arbitrary SQL projections too. A pipe or embedded newline in a query result previously broke the rendered table's column alignment or ended a row mid-cell; `structuredContent.rows` is unchanged — display-only. ([#8](https://github.com/cyanheads/openaq-mcp-server/issues/8))
- **`openaq://location/{locationId}` and `openaq://parameters` declare error contracts** — both resources now list `errors[]` and route failures through `ctx.fail`/`ctx.recoveryFor` instead of throwing bare. `location` covers `invalid_location_id`, `location_not_found`, `upstream_error`, `rate_limited`, `upstream_timeout`, and `invalid_api_key`; `parameters` reuses the existing `withUpstream` helper (`src/mcp-server/tools/shared/upstream-errors.ts`, unmodified) for the same four upstream transport reasons. Every failure now carries a `reason` and a `recovery` hint instead of a bare code. ([#20](https://github.com/cyanheads/openaq-mcp-server/issues/20))
- **`extractValidationMessage` handles all four of OpenAQ's 422 body shapes** — a pydantic `{"detail":[{...,"msg":...}]}` array, a flat `{"detail":"..."}` string (the shape OpenAQ also uses for 404s), a bare JSON string, and the JSON-string-wrapped Python repr. Previously only the Python-repr shape was read; the other three fell through to the generic "OpenAQ rejected the request parameters." message, discarding the actual parameter name and bound. ([#21](https://github.com/cyanheads/openaq-mcp-server/issues/21))
