# 0.4.0 — 2026-09-26

## Added

- **`openaq_dataframe_drop`** deletes a whole tenant-scoped canvas and returns `canvasId` plus `dropped`. Enable with `OPENAQ_ENABLE_CANVAS_DROP=true` and `CANVAS_PROVIDER_TYPE=duckdb`; callers sharing an id within the same tenant share deletion access.
- **Canvas configuration** is forwarded through both plugin configurations, the MCP Registry metadata, and the MCPB manifest; the portable MCPB bundle still omits DuckDB's native binding.

## Changed

- **HTTP client migration** — MCP SDK 2.1, through mcp-ts-core 0.13.9, requires `MCP-Protocol-Version` on 2026-07-28 HTTP envelopes. Clients relying on the prior malformed-request behavior must send the header; missing headers return HTTP 400 / `-32020`.
- **Output-error migration** — mcp-ts-core 0.13.8 changes output-contract failures from `-32007` to `InternalError` (`-32603`) without `data.issues`. Update client handling of those failures; the seven existing tool schemas are unchanged.
- **Docker telemetry installs** preserve Bun's release-age and Socket scanner checks, install optional peers at the framework's supported ranges, and include OTLP log packages. Bun package-manager and image pins move to 1.4.2; the minimum remains 1.4.0.
- **Packaging and development checks** exclude built MCPB archives from npm and logs/design sketches from MCPB; synchronized framework scripts fail on definition-load errors, check manifest versions and Docker build platforms, and validate release annotations. Framework guidance is synchronized too.
- **Configuration documentation** covers OTLP endpoints and failure-payload logging, clarifies session overrides, and reconciles the canvas lifecycle and measurement-staging design.

## Fixed

- **Measurement canvas precision** — all seven numeric columns use nullable `DOUBLE`, preserving fractional readings, statistics, and coverage after leading zeros or nulls; timestamps remain `VARCHAR` and flags remain `BOOLEAN`. Real DuckDB regressions cover query/text parity and canvas reuse. ([#45](https://github.com/cyanheads/openaq-mcp-server/issues/45))
